# Service Token Authentication

Services can make calls to gateway endpoints via pre-shared keys.

To set this up to test do the following.

1. Start a gateway instance
1. Start a controller instance
1. Get your service UUID from controller: `awx-manage shell -c "from ansible_base.resource_registry.models.service_identifier import ServiceID ; print(ServiceID.objects.first().id)"`
1. Open Shell Plus from gateway and issue the following commands:
   ```
   sc = ServiceCluster.objects.get(name='controller')
   sc.service_id = '<output from the AWX command>'
   sc.save()
   ```
1. Generate a secret key for controller: `gw-manage generate_service_secret controller`

1. In the controller instance add the following settings:
    RESOURCE_SERVER = {
        'URL': "https://<IP or name for controller to contact gateway at>:8000",
        'SECRET_KEY': '<generated secret key>'
        'VALIDATE_HTTPS': False,
    }

Now we can generate a JWT request from controller for gateway: `awx-manage shell -c 'from ansible_base.resource_registry.resource_server import get_service_token ; print(get_service_token(expiration=3600))'`
Copy and paste this output into an environment variable like TOKEN and then we can use it via curl to call resources on the gateway:
`curl -k https://localhost:8000/api/gateway/v1/settings/analytics/ --header "X-ANSIBLE-SERVICE-AUTH: $TOKEN"`

NOTE: its hard to wrap awx-manage in `$()` to auto create the environment variable because there are hidden characters being generated by docker/awx-manage so copy/paste is a bit easier.
You could also use pythons `requests` page to make the calls.


# Allowing access to a view via Service Token Authentication

To make a view accessible via ServiceTokenAuthentication we need to edit `aap_gateway_api/authentication/service_token_auth.py`. 

The `ServiceTokenAuthentication` class has a property called `authorized_paths` which defines authorized paths.
Its an array of tuples with the following elements in them:
    1. The view name used to do a reverse lookup
    2. Any kwargs to pass to the lookup
    3. Which methods are allowed

This should handle most cases of access. However, there may be times when you need to grant the incoming user additional permissions. An example of this can be found in the `is_user_authorized` method. This is currently implemented for the `service-index-root` endpoint. 

Additionally, if the view you are granting access to is protected by the `isSuperUserOrAuditor` or `isSuperUser` permission classes you need to add a property to your view called `allow_service_token` and set it to True. This will allow the permissions classes to return True if the requesting user is the system user.
